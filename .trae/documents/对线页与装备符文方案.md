# 对线页 + 装备符文方案系统

## Context（背景与目标）

里程碑 3 的核心。首页搜索英雄后进入 `/matchup?champion=xxx`，当前 [MatchupView.vue](file:///Volumes/t1/Permanent/LOL/frontend/src/views/MatchupView.vue) 仅占位。本期按 [对线页面.html](file:///Volumes/t1/Permanent/LOL/design/对线页面.html) 真实建设：

1. **英雄横幅**：头像/短名/称号/官方定位标签/收藏占位（数据已齐：Hero.avatar/title/name/roles）。
2. **推荐装备 & 符文**：建后端方案表，**仅管理员**在独立制作页（迁移 [装备符文页面.html](file:///Volumes/t1/Permanent/LOL/design/装备符文页面.html)）为英雄维护多套官方方案，对线页真实读取展示，普通用户只浏览。符文用 Data Dragon **真实图标**，需补全「系→排→基石」层级并新增属性碎片图标。
3. **相关内容**（视频/图文九宫格，属里程碑 4）：保留全部/视频/图文筛选、对位英雄搜索、九宫格、分页结构，本期数据恒空显示「暂无相关内容」，上传/发图文按钮保留并 toast 占位。

已核实的关键事实：
- 16.20.1 五系符文 `slots` 每排数量：精密(8000)/巫术(8200) 基石=**4**，主宰/启迪/坚决基石=3；三小排均 3。前端必须按数据渲染，不能写死。
- 属性碎片图标在 Riot 官方源 `cdn/img/perk-images/statmods/*` 返回 **403**（大小写均是）；Community Dragon 镜像 200。9 槽对应 6 张图（已逐一验证 200），基址 `https://raw.communitydragon.org/latest/plugins/rcp-be-lol-game-data/global/default/v1/perk-images/statmods/`，文件全小写：
  - 第1行：适应之力 `statmodsadaptiveforceicon` / 攻速 `statmodsattackspeedicon` / 技能急速 `statmodscdrscalingicon`
  - 第2行：适应之力 / 护甲 `statmodsarmoricon` / 魔抗 `statmodsmagicresicon`
  - 第3行：生命 `statmodshealthscalingicon` / 护甲 / 魔抗

## 一、后端

### 1. 新增模型 `internal/model/rune.go`
- `RuneTree{ID int64 primaryKey(=DD系id 8000…); Key; Name; Icon; Sort int; Runes []Rune gorm:"foreignKey:TreeID"}`
- `Rune{ID int64 primaryKey(=DD符文数字id); TreeID int64 index; Name; Icon; Row int(0基石/1-3); IsKeystone bool; Sort int}`
- 现有平铺 `GameAsset(category=rune)` **保留不动**，后台管理页符文只读网格继续用它（AdminView 零改动）；新表仅供制作器与对线页。

### 2. 新增模型 `internal/model/build_plan.go`（表名 `build_plans`）
- `ID; HeroID int64 gorm:"uniqueIndex:idx_hero_seq,priority:1"; Seq int priority:2; AuthorID int64; Vs string size:255; 时间戳`
- `Items BuildItems gorm:"type:json;serializer:json"`、`Runes BuildRunes gorm:"type:json;serializer:json"`（GORM 内置 json serializer，MySQL JSON 列，**必须双 tag**）
- `BuildItems{ Start,Summs []*int64(len2); Mid []*int64(len5); Core []*int64(len6); Final []*int64(len7) }`（空槽 `null` 用 `*int64`；summs 槽引用 category=skill，其余 item）
- `BuildRunes{ Primary int64(主系id); PrimaryPicks []int64(len4=[基石,排1,排2,排3]存符文DDid); Secondary int64; SecondaryPicks []*int64(len3,nil=该排不选); Shards []int(len3,存0-2) }`

### 3. 属性碎片常量 `internal/ddragon/shards.go`
- `type ShardDef{File,Name string}`；`var ShardGrid [3][3]ShardDef` 按上面 9 槽映射；`var ShardFiles []string` 去重 6 个文件名。
- [client.go](file:///Volumes/t1/Permanent/LOL/backend/internal/ddragon/client.go) 加 `CDragonBaseURL` 与 `OpenShardIcon(ctx,file)`（走 Community Dragon）。

### 4. 同步改造 [sync_service.go](file:///Volumes/t1/Permanent/LOL/backend/internal/service/sync_service.go)
- 符文 runeJobs：`for _,slot` 改 `for slotIdx,slot`，apply 时除原 GameAsset upsert 外，同时 upsert `RuneTree(id/key/name/icon/sort)` 与 `Rune(id/treeId/name/icon/row=slotIdx/isKeystone=slotIdx==0/sort)`；图标仍走 `OpenIconGlobal`（Styles 已验证 200，沿用 `icons/runes/{id}.png` 幂等落盘，不重复下载）。
- 新增「同步属性碎片」阶段：对 6 个去重文件发 iconJob（dir=`shards`，用 `OpenShardIcon`），失败计入 failedTotal（不写版本可重试；常量即兜底）。
- `NewSyncService` 构造函数加 `runeRepo *repository.RuneRepository` 参数，[main.go](file:///Volumes/t1/Permanent/LOL/backend/cmd/api/main.go) 同步改装配。

### 5. 仓储 / 服务 / 处理器
- `repository/rune_repository.go`：`UpsertTree/UpsertRune`、`ListTreesWithRunes()`（系按 sort、符文按 sort）。
- `repository/build_plan_repository.go`：`ListByHero(heroID)`（seq 升序）、`ReplaceAllInTx(heroID, []BuildPlan)`（事务 delete+insert）。
- `service/build_plan_service.go`：`ReplaceByHero(heroID, authorID, []planInput)` —— 校验并中文报错（`ValidationError`）：五分区长度 2/2/5/6/7；装备 id 一次 `WHERE id IN` 验存在，summs 槽必须 category=skill、其余必须 item；主副系存在且不同；picks 符文须归属对应系且排次正确；英雄不存在返回 404。`seq` 服务端按数组下标 +1 重排。
- handler：
  - 公开：`AssetHandler.List`（复用 `AssetRepository.List`）；`RuneHandler.Trees`（返回 `{trees, shards}`，shards 用 `store.IconURL("shards",file)` 拼 URL）；`BuildHandler.ListByHero`。
  - 管理员：`BuildHandler.ReplaceByHero`，用 `middleware.UserID(c)` 写 AuthorID。

### 6. 路由（[main.go](file:///Volumes/t1/Permanent/LOL/backend/cmd/api/main.go)）

## 三、实施顺序

1. 模型 rune.go/build_plan.go + AutoMigrate；shards.go 常量 + CDragon client。
2. sync 改造（符文双写 + 碎片阶段）+ RuneRepository + NewSyncService 装配。
3. build_plan 仓储/服务/处理器 + 公开/管理员路由 + 公开 assets/rune-trees。
4. `docker compose up -d --build --force-recreate api`，管理员触发一次同步（POST `/api/admin/sync/ddragon`，无需 force，版本相同会 skip——故符文双写需要 force:true 跑一次，或临时直接校验 Rune/RuneTree 落库）。
5. 前端展示（api → ItemSlots/RunePage/BuildPanel → MatchupView）。
6. 前端制作器 BuildEditorView + /build 路由。
7. `--force-recreate frontend`，端到端走查。

> 注：Rune/RuneTree 新表在版本未变时不会被普通同步填充；实施第 4 步用 `{"force":true}` 全量重跑一次（图标幂等跳过，只补结构化表）。

## 五、风险点

- **基石 3/4 不一**：严格按 Rune 数据渲染。
- **Community Dragon 国内可达性**：碎片下载失败只告警、不阻断英雄/装备；`Failed>0` 不写版本可重试；前端 `<img>` 图标加载失败走占位底图。
- **JSON tag**：`type:json;serializer:json` 必须双 tag；`[]*int64`(null 槽) 与 `[]int`(shards) 不混用。
- **champion 匹配不到**必须有空态。
- **asset id 稳定性**：sync 按 category+name upsert 不新增/删除 id，方案引用长期有效。
- **切符文系**：制作器切系重置该系 picks；展示端查不到符文 id 则不高亮。
