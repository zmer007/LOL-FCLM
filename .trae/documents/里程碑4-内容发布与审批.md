# 里程碑 4：视频/图文发布 + 审批 + 对线页接通 + 详情页

## Context

用户在对线页点「上传视频 / 发布图文」投稿，内容内嵌推荐装备&符文；提交后进入管理员审批；通过后：
1. 出现在对线页「相关内容」九宫格；
2. 其内嵌的装备符文被提取为对线页「推荐装备 & 符文」方案（**取代刚下线的管理员独立 BuildPlan 体系**）。
用户可编辑自己的任意内容，保存后回到 pending；**已通过内容在复审通过前继续展示旧版**。视频限 MP4/H.264 ≤200MB 不转码。

关键设计：九宫格查询条件是 `hero_id=当前英雄 OR opponent_hero_id=当前英雄`——前者是本英雄视角（卡片标青色「操作你」，其装备符文计入推荐），后者是对位英雄发的打当前英雄的攻略（标红色「被操作」，不计入本英雄推荐）。

## 一、后端

### 1. 内容模型 `internal/model/content.go`（表 `contents`）
```
ID, AuthorID(index), HeroID(主视角), OpponentHeroID(对位,必填),
Kind string  // video | article
Title string(120), Body text          // 视频简介 / 图文正文
VideoURL string(255), DurationSec int // video
Images []string `serializer:json`    // article 多图
Items BuildItems `type:json;serializer:json`   // 复用 build_plan.go 的结构
Runes BuildRunes `type:json;serializer:json`
Status string // pending | approved | rejected（默认 pending，索引）
RejectReason string(255)
Approved *ContentSnapshot `type:json;serializer:json` // 最近通过快照，null=从未通过
Views int, 时间戳
```
- `ContentSnapshot{Title,Body,VideoURL,Images,Items,Runes,OpponentHeroID,DurationSec,ApprovedAt}` —— 对外列表/详情只读它；编辑改实时字段并把 Status 重置 pending，Approved 保留 → 复审期间旧版继续展示。
- 状态常量 `ContentPending/Approved/Rejected`、`KindVideo/KindArticle`。

### 4. 分层（复用现有范式）
- `repository/content_repository.go`：Create/Update/Get/Delete、`ListPublic(heroID, opponentFilter, kind, page,size)`（条件 `status=approved AND (hero_id=? OR opponent_hero_id=?)`，按 created_at desc，分页返回 total）、`ListByAuthor(uid,status)`、`ListPending(page,size)`、`IncrViews`（`UPDATE ... SET views=views+1`）。
- `service/content_service.go`：
  - 接收 multipart 解析后的 DTO + 文件；校验：标题 1-120 rune、对位英雄必填且存在且≠主英雄、装备五分区长度与素材类别（复用刚写的 build_plan_service 校验逻辑，下沉为 `validateItems/validateRunes` 公共函数，签名去掉 BuildPlan 语义）、视频类必须有 video 文件（编辑时未换文件则沿用旧 URL）、图文类图片张数 ≤9、视频大小/MIME 由 store 兜底。中文 ValidationError。
  - Create：status=pending、Approved=nil；Update（仅作者）：更新实时字段+视频/图片、status=pending、RejectReason 清空、**不动 Approved**。
  - Approve（管理员）：把实时字段拷进 Approved（带 ApprovedAt）、status=approved。
  - Reject（管理员，理由必填 ≤255）：status=rejected、写理由、不动 Approved（曾通过的旧版继续展示）。
- `handler/content_handler.go`：multipart 表单字段 `meta`（JSON 字符串：title/body/heroId/opponentHeroId/kind/items/runes/keptImages/durationSec）+ 文件 `video` 或 `images`（多图）。对外详情组装作者名+双英雄信息。
- 路由（[main.go](file:///Volumes/t1/Permanent/LOL/backend/cmd/api/main.go)）：
  - 公开：`GET /api/contents`（列表）、`GET /api/contents/:id`（approved 或本人/管理员可见；approved 时 IncrViews）、`GET /api/heroes/:heroId/builds`（聚合：approved 且 `hero_id=?` 的内容，仅取装备或符文非空的，从 Approved 快照组装 `{contentId,kind,title,opponentHeroId,vs,items,runes}`）。
  - 登录：`POST /api/contents`、`PUT /api/contents/:id`、`DELETE /api/contents/:id`（作者或管理员）、`GET /api/my/contents`。
  - 管理员：`GET /api/admin/contents?status=pending`、`POST /api/admin/contents/:id/approve`、`POST /api/admin/contents/:id/reject`。
- AutoMigrate 追加 Content。

## 四、验证
- curl：普通用户 POST multipart 视频（含 meta+装备符文）→ pending；非法（无标题/无对位/主副同系/超 200MB/非 mp4）→ 400 中文；管理员列表看到、approve 后公开列表出现、详情可播；reject 要有理由。已通过内容作者 PUT 修改后再查公开详情仍是旧快照、状态 pending；再次 approve 后刷成新版。「被操作」：用对位英雄视角发一条，主英雄对线页九宫格出现红标但 builds 不含它。删除（非作者 403）。
- 浏览器：对线页发视频/图文（登录回跳）→ 我的页审批中可见 → 管理员通过/拒绝（理由可见）→ 对线页九宫格与推荐装备符文出现 → 详情页播放/看图 → 作者编辑重审（旧版仍可见）→ 铁男等别名上下文正确。

## 五、风险/注意
- axios FormData boundary、Nginx 已有 `client_max_body_size 220m`（无需改）；Gin 流式落盘避免 OOM。
- 视频编码只校验容器 MIME，不验证 H.264（浏览器不能播由用户负责，提示文案注明）。
- 双英雄头像封面本期纯 CSS 拼合，worker 合成留二期。
- 替换视频/图片后旧文件成为孤儿，本期不清理。
- 点赞/收藏/分享/评论本期不在范围内，详情页操作栏保留样式但 toast 占位。
